# 段階3の修正版：ページを残す対象外・速度・表示

938489bの実機試験では、本人識別、DRY_RUN、確定・修正・保留、途中停止からの再実行、2タブのversion検知が合格しました。対象外のNotion処理がゴミ箱になることをユーザーが確認し、該当テストページを復元済みです。この修正版はゴミ箱操作を廃止します。GASの実行・デプロイ・実サービス更新はユーザーが行います。

## finance@のGASへ反映する順番

1. finance@の「MTG議事録自動化・本体」で、`dist/gas-core/Code.gs`をコード.gsに全文置換します。HTMLの **Index、Styles、Scripts** も、dist/gas-coreの同名HTMLで全文置換します。dev.gsは残します。manifestは前版と同じです。
2. 新しいスクリプトプロパティはありません。ENV=test、REVIEW_MASTER_ACCESS=falseと既存のテスト用ID・NOTION_TOKEN・WEBAPP_URLを維持します。REVIEW_TEST_FAIL_STEPは通常は削除してください。
3. DRY_RUN=trueで **setupReviewNotionStatus()** を実行します。「確認状態」の追加予定と既存ページ3件の状態更新予定が出ます。Notion・議事録行には書き込みません。dry_run_logだけ増えます。
4. `devDryRunOff()`でfalseにし、**setupReviewNotionStatus()** を実行します。確認済みテスト議事録DBだけに「確認状態」（select）を追加し、不足選択肢だけ補い、既存ページに台帳の状態を反映します。既存項目・選択肢は削除・改名しません。ページ名・本文・関連プロジェクトは変更しません。準備関数は繰り返し実行できます。途中で止まった場合も同じ関数で続けられます。
5. `devDryRunOn()`でtrueに戻します。03は対象外のまま、Notionにページが残り、確認状態が対象外になっていることを確認します。復元が未完了なら関数は所属・状態の事前検証で停止します。自動復元はしません。
6. GASの「デプロイ」→「デプロイを管理」→既存Webアプリの編集→バージョンを **新バージョン** にしてデプロイします。「実行：自分（finance@）」「アクセス：自分のみ」は維持します。URLは変わりません。開いているタブは再読み込みしてください。ブラウザに古い画面が残る場合は **cmd+shift+R（WindowsはCtrl+Shift+R）で強制再読み込み** してください。

setupReviewAccess、setupSharedTestWorkspace、seedFixtureInbox、ingestInbox、テストDBの再作成は今回不要です。NOTION_FIXTURE:*や台帳行も消しません。準備で各行のversionが増えるため、旧タブの操作は拒否されます。

## Notionの確認状態

選択肢は、確認待ち／仕分け待ち／確定／確定・修正あり／保留／対象外／対象外（Meet優先）／要対応です。独自の既存選択肢は保持します。既存「確認状態」がselect以外なら変更せず停止します。

- 対象外：会議フォルダを_test/99_対象外へ移動し、Notionページは **確認状態だけ「対象外」** に変更します。ページを残し、本文・タイトルは維持します。archived／in_trashは送信しません。
- 保留：フォルダは変えず、Notionの確認状態を「保留」にします（前版からの変更です）。
- 確定・修正：従来の3項目と確認状態を更新します。
- 新しい取り込み：確認状態の項目と一致する選択肢があれば、作成時にも取り込み判定の状態を入れます。

既定のNotion一覧で対象外を隠すには、テスト議事録DBの普段使うビューに **確認状態が「対象外」ではない、かつ「対象外（Meet優先）」ではない** というフィルターを手で追加します。必要なら対象外専用ビューも作れます。ビュー設定はこのGASでは変更しません。

本番にはコードから項目追加・ページ更新しません。本番移行を人が承認した後、管理者が本番議事録DBに同じ「確認状態」（select）と選択肢、ビューのフィルターを作成する手順を別途実施してください。ENVやIDを変更するだけでは、この版の本番書き込み禁止は解除されません。

旧版の処理記録は保持します。未完了の旧対象外処理を再開する場合は状態更新に読み替え、ゴミ箱処理には戻りません。

## 速度の変更点と計測

- 台帳はリクエストごとに使用シートの見出しとデータをまとめて1回取得し、同じシートを繰り返し読みません。権限・versionは毎回新しく読みます。
- 準備関数が既存3件の要約・提案件数をstep_done_json内に保存します。一覧で毎回Driveの判定JSONを読みません。今後の取り込みでも同じ情報を記録します。長大な要約はセル上限を避けてJSONから読みます。
- 表示用の候補・JSON・スキーマはCacheServiceで120秒だけ再利用します。候補は毎回最新マスタで閲覧範囲を絞ります。キャッシュがなくても読み直して動きます。
- 詳細表示ではNotion APIを呼びません。Notionリンクは台帳のページIDから表示します。Driveは同じ祖先を1要求内で再取得せず、ファイルの確認も会議フォルダの一覧1回にまとめます。
- 更新時はNotionスキーマ・実ページ所属・Drive範囲を改めて検証します。関連プロジェクトがない場合はタスクDBを取得しません。Notionの待機は通信時間を除いた必要分だけです。
- 通常操作後の通信はreviewSubmitの **1回だけ**。返却された該当行と詳細を使い、bootstrap→一覧→詳細の3回の追加通信をやめました。他の行を取り直すときは「一覧を更新」を押せます。

画面の「直近の通信時間」と、GASの実行ログ「確認画面 初期表示／詳細／操作：…ms」を確認してください。初回と再表示を分けて測れます。数秒を目標に呼び出し数を削減していますが、実サービスの待ち時間はローカルのモックでは測定できません。実機での改善幅は未確認です。
