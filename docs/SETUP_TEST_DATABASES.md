# テスト用Notionデータベースの初期作成

この操作はユーザーがGASで実行します。Codex側ではGAS実行・Notionへの書き込みを行っていません。

## 貼り付けるファイル

GASの「MTG議事録自動化・本体」を `finance@premiere-mode.co.jp` で開きます。
GitHubの `work` ブランチにある **`dist/gas-core/Code.gs`** をダウンロードし、テキストエディタで開いて全文をコピーしてください。
GASの「コード.gs」を全文置換して保存します。GitHubのプレビュー表示の一部分だけをコピーしないでください。
同じ関数を個別ファイルにも貼っている場合は重複させず、一括版か個別版のどちらかを使ってください。

`UrlFetchApp` を使います。新規GASプロジェクトの既定スコープでも権限確認が出ます。
スコープを明示管理している場合は `https://www.googleapis.com/auth/script.external_request` が必要です。
この初期化にはDrive・CalendarのAdvanced Service、台帳ID、tl;dv受信DBの設定は不要です。

## 設定するスクリプトプロパティ

GAS左側「プロジェクトの設定」→「スクリプト プロパティ」に設定します。

| キー | 値 |
|---|---|
| `ENV` | `test` |
| `DRY_RUN` | `true` のまま維持 |
| `SETUP_CREATE_TEST_DB` | `true` |
| `NOTION_TOKEN` | 「MTG議事録連携（GAS）」のシークレット |

トークンはチャットやGitに入れません。このコードはトークンの名前・所有者を判定できないため、設定者が正しいインテグレーションを選びます。
管理用ページ、本番MTG議事録、本番プロジェクト・タスクへのアクセスが必要です。インテグレーションの読み取り、挿入、更新権限も確認してください。

`SETUP_CREATE_TEST_DB=true` は、この関数だけでテスト用DBの作成・リレーション追加を許可する専用フラグです。
この初期化は `DRY_RUN=true` でも実際にテストDBを作ります。他の連携処理のDRY_RUNを解除するものではありません。
既存の `NOTION_DB_MINUTES_TEST` に入ったポータルのIDは、この関数の入力には使いません。

## 実行

1. GASのエディタ上部で **`setupTestDatabases`** を選び、「実行」を押します。
2. Googleの権限確認が出たら内容を確認して許可します。
3. 成功したら実行ログの `NOTION_DB_MINUTES_TEST = ...` と `NOTION_DB_TASKS_TEST = ...` を、それぞれ同名のスクリプトプロパティへ保存します。関数はこの設定を自動で上書きしません。
4. `SETUP_CREATE_TEST_DB` を `false` に戻します。

## 作成先と保護

- 親ページは「議事録システム（管理用・contact@のみ）」 `400ca178-7419-80e8-bb9a-f157874b6105` に固定します。ページ名は元の表示名であり、GAS所有者を示すものではありません。
- 本番MTG議事録 `4cf02dee-7a11-4319-ace1-e866d6a1a914`、本番プロジェクト・タスク `e321f1cb-3365-4a2c-9844-47f34734a9d7` は、DBとデータソースの項目構成をGETで読むだけです。本文は複製しません。
- 新規DBは「MTG議事録（テスト）」「プロジェクト・タスク（テスト）」です。同じ親の直下に同名DBがあれば再利用し、IDを返します。同名が複数ある場合、既存項目の型・選択肢が異なる場合は上書きせず停止します。
- 関連するプロジェクト⇔関連するMTGはテスト用データソース間の双方向リレーション、親アイテムはテスト用タスクへの自己参照にします。元スキーマの他の対応可能な内部リレーションも置き換えます。
- 本番データソースID、対象外データソースへのリレーションは禁止します。既存のリレーションが異なる場合は付け替えず停止します。
- 途中で失敗しても削除・ロールバックはしません。既に作成したDBのIDはその時点でログに出します。再実行すると既存DBを検出し、不足DB・不足リレーションのみ作成します。
- 同一GASプロジェクト内の並行実行はロックで抑止します。別GASプロジェクトから同時に初期化しないでください。

## 複製しない型

`formula`、`rollup`、未対応の型と、複製対象外DBへのリレーションは名前・型・理由をログに残してスキップします。
`status` も、API `2025-09-03` の作成指定では独自の選択肢を保持できないためスキップします。別の型へ置き換えることはしません。
`select`・`multi_select` は選択肢名・色・順序を複製し、本番側のoption IDは送りません。
Notion-Versionは、他のスクリプトプロパティに関係なく `2025-09-03` に固定します。

## ローカル検証

```sh
npm run smoke
npm run build
```

公式の作成・更新仕様と、`makenotion/notion-sdk-js` の `v5.0.0/src/api-endpoints.ts` の2025-09-03対応型を確認しています。
